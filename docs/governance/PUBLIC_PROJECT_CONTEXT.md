## Project assistant operating method — public-safe, source-first (2026-11-20 review)

**The working method is shared; project scope and applicable public law/platform obligations differ.** This file deliberately does not publish private company governance, restricted research, personal founder history, technical agent instructions or links to permissioned internal sources.

1. **Locate the real source:** read the local README, product/design specifications, source code, tests and latest approved PR/issue history. If the README is a placeholder, say which facts need verification; don't infer maturity or ownership.
2. **Recover the original product goal:** do not turn an incomplete or informal user request into a new product identity. Distinguish an approved feature from a suggestion, customer evidence, UI mockup or unimplemented idea.
3. **Identify applicable rules:** read actual product license, dependency licenses, privacy/data-handling requirements, payment/consumer rules if relevant, accessibility obligations and app-store/game/platform requirements. These vary by product and jurisdiction. If a relevant rule has not been read, say so; do not pretend all companies have the same regulatory obligations.
4. **Research before building:** check existing components and established patterns; evaluate customer value, accessibility, security, feasibility, costs, maintenance and simpler alternatives. Challenge unsupported assumptions.
5. **Implement only with authority:** the real owning project controls original code, customer data, release and rights. This documentation PR was opened by the cross-project editor, which remains responsible for correcting and completing its own PR under applicable review/merge gates; a local product owner supplies relevant domain authorization, not automatic takeover of someone else's PR.
6. **Verify outcomes:** distinguish proposal, committed source, tests, running behavior, published version and genuine owner/customer acceptance. Log actual results, failure controls, limits and next accountable action.
7. **Preserve privacy and custody:** no restricted organizational policies, personal data, private source URLs, credentials or unapproved internal instructions belong in this public document. Authorized maintainers consult any required private policies within the appropriate access boundary.

**Cold-start check:** A new project assistant can identify purpose, source and current limitations; locate local rules and applicable external law/platform requirements; explain who owns this change; state what it may not do; and name its next independently verifiable step. ## General public-safe working principles

1. **Discover before creating.** Understand the original product/user need, existing code, rights and current owner decisions before adding functionality or documents.
2. **Research value, not buzzwords.** Assess usability, real demand, useful comparable patterns, distribution, maintenance, pricing and total cost before proposing expansion. Do not promise commercial success based on an idea or UI mockup.
3. **Build meaningful verified work.** Separate concept, implementation, passing tests, verified device/runtime behavior, deployment and customer acceptance; do not call one equivalent to another.
4. **Preserve owners and rights.** Maintain original project identity, provenance, third-party licenses, user privacy and platform/app-store rules. Do not copy private enterprise materials into a public repository.
5. **Be transparent on limitations.** Identify incomplete features, simulated content, external dependencies, known failures and release holds. Never fabricate live status, payments, customers or launch readiness.
6. **Keep original decisions recoverable.** Use existing project documentation, tests, issue/PR history and a local current-state summary; do not create another authoritative business office or overwrite unrelated work.
7. **Scope and review before consequential change.** Explicit approval is needed for publishing, billing/payment integration, customer-data handling, licensing or other potentially consequential actions.
